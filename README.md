# Прогнозирование дождя в Австралии

Исследование погодных наблюдений из датасета **Rain in Australia**: анализ данных, проверка гипотез и сравнение моделей бинарной классификации. Цель — предсказать, будет ли дождь на следующий день (`RainTomorrow`: `Yes` / `No`).

## Датасет и причины выбора

Использован [Rain in Australia на Kaggle](https://www.kaggle.com/datasets/jsphyg/weather-dataset-rattle-package), файл `weatherAUS.csv`. В загруженной в ноутбуке версии — **145 460 строк и 23 столбца**. Данные содержат дату, местоположение и погодные показатели: температуру, влажность, давление, осадки, облачность, солнечные часы и характеристики ветра.

Датасет подходит для исследования, потому что задача прогноза имеет понятную интерпретацию, а данные позволяют сравнить работу моделей с числовыми и категориальными признаками. Пропуски, дисбаланс классов и временная структура дают возможность проверить разные способы предобработки и оценки качества.

**Датасет не включён в репозиторий.** Для повторного запуска его нужно получить по ссылке выше.

## Первоначальные гипотезы

Ниже приведены первоначальные предположения, зафиксированные в ноутбуке. Итоговый список экспериментов уточнялся по ходу исследования.

1. Дневная влажность (`Humidity3pm`) информативнее утренней (`Humidity9am`).
2. Местоположение и сезон повышают ROC-AUC.
3. Случайный лес превосходит логистическую регрессию.
4. Accuracy недостаточно отражает качество при дисбалансе классов.
5. Удаление признаков с долей пропусков более 40% не ухудшит качество.
6. Исключение `Sunshine` и `Evaporation` не ухудшит ROC-AUC.

## Что сделано

- Изучены структура данных, распределение цели, пропуски и связь погодных признаков с дождём на следующий день.
- Сравнены DummyClassifier, Logistic Regression, Decision Tree и Random Forest.
- Проверены регуляризация, сложность деревьев, настройка случайного леса, индикаторы пропусков, отбор признаков и сезонность.
- Предобработка выполняется внутри `Pipeline`: медиана и масштабирование для числовых признаков, наиболее частое значение и One-Hot Encoding для категориальных.
- Для подбора конфигураций использованы три временных фолда по уникальным датам. Финальный тест — отдельный период **с 8 августа 2015 года**: 32 891 строка. До него — 109 302 строки.
- `RainTomorrow`, исходная дата и возможный `RISK_MM` исключены из входных признаков. В использованном CSV `RISK_MM` отсутствует.

## Краткие результаты

### Первоначальные предположения

| Предположение | Результат |
| --- | --- |
| `Humidity3pm` информативнее `Humidity9am` | По индивидуальному F-score `Humidity3pm` оказался наиболее информативным признаком. Отдельного сравнения моделей с исключением каждого из двух признаков нет. |
| Местоположение и сезон улучшают прогноз | `Location` использован в моделях, но его отдельный вклад не проверен. Добавление сезонности дало лишь +0.0002 к среднему CV ROC-AUC. |
| Random Forest лучше логистической регрессии | Среди выбранных конфигураций не подтвердилось: настроенный лес получил CV ROC-AUC 0.8702, логистическая регрессия с индикаторами пропусков — 0.8717. |
| Одной Accuracy недостаточно | Подтвердилось на начальной валидации: DummyClassifier получил Accuracy 0.7801, но Recall и F1 для дождя равны 0. |
| Можно удалить все признаки с пропусками более 40% | Совместное удаление таких столбцов не проверялось; общего вывода нет. |
| Можно исключить `Sunshine` и `Evaporation` | Совместное исключение не проверялось. Удаление только `Sunshine` вместе с его индикатором ухудшило CV ROC-AUC с 0.8717 до 0.8690. |

### Итоговые эксперименты

| Гипотеза | Результат | Вывод |
| --- | --- | --- |
| H1. `Sunshine` полезен для прогноза | CV ROC-AUC: 0.8690 без признака и его индикатора → 0.8717 с ними | Поддерживается на всех трёх фолдах. |
| H2. Индикаторы пропусков улучшают качество | CV ROC-AUC: 0.8691 → 0.8717 | Поддерживается; проверен набор индикаторов целиком. |
| H3. Слишком сложное дерево переобучается | При увеличении глубины с 7 до 20 Train ROC-AUC вырос с 0.8630 до 0.9890, Validation ROC-AUC упал с 0.8412 до 0.6814 | Поддерживается. |
| H4. Настройка L2-регуляризации улучшает модель | CV ROC-AUC: 0.8686 при `C=1` → 0.8691 при `C=0.1` | Частичная поддержка: прирост очень мал. |
| H5. Настройка Random Forest улучшает качество | CV ROC-AUC: 0.8612 → 0.8702 | Поддерживается в рамках проведённого поиска. |
| H6. Отбор 20 признаков не ухудшит качество | CV ROC-AUC: 0.8717 → 0.8653 | Не подтвердилась. |
| H7. Признаки месяца заметно улучшают прогноз | CV ROC-AUC: 0.8717 → 0.8719; на одном фолде качество снизилось | Убедительной поддержки заметного улучшения нет. |

Числа взяты из сохранённых выводов `research.ipynb`. Временная кросс-валидация, начальная валидация и финальный тест — разные оценки. Статистическая значимость различий отдельно не проверялась.

### Финальная модель

Выбрана **логистическая регрессия с L2-регуляризацией (`C=0.1`) и индикаторами числовых пропусков**, без отбора признаков и сезонных столбцов. Порог классификации — **0.5**.

| Метрика на отложенном тестовом периоде | Значение |
| --- | ---: |
| ROC-AUC | 0.8628 |
| Accuracy | 0.8473 |
| Precision | 0.7240 |
| Recall | 0.4906 |
| F1 | 0.5849 |

Главное ограничение модели — Recall: обнаружено 3538 из 7211 наблюдений с дождём на следующий день, то есть примерно половина. Precision, Recall и F1 рассчитаны для положительного класса `Yes`.

## Как открыть и запустить

Результаты можно просмотреть в [research.ipynb](research.ipynb) без запуска ячеек.

Для повторного выполнения:

1. Скачайте `weatherAUS.csv` со [страницы датасета](https://www.kaggle.com/datasets/jsphyg/weather-dataset-rattle-package).
2. Откройте ноутбук в Kaggle и подключите этот датасет либо используйте локальный Jupyter.
3. Для локального запуска установите зависимости:

   ```bash
   pip install numpy pandas matplotlib scikit-learn jupyter
   ```

4. При локальном запуске замените значение `file_path` в ячейке загрузки на путь к своему `weatherAUS.csv`. В ноутбуке сохранён путь Kaggle: `/kaggle/input/datasets/jsphyg/weather-dataset-rattle-package/weatherAUS.csv`.
5. Выполните ячейки по порядку. Подбор гиперпараметров может занять время.

Версии библиотек исходного запуска не зафиксированы, поэтому при повторном выполнении возможны небольшие отличия результатов.
